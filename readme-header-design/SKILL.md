# README header 设计

本文改编自 oil-oil/beautify-github-readme（MIT 许可）的头图指南与 SVG 制作指南，经翻译、删改与补充；部分参数来自对其示例 SVG 的实测，只作起点。上游的版权与 MIT 许可全文见同目录的 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)，复制本 skill 时请连同它一起复制。

## 范围与边界

- 只产出 header/hero 的静态 SVG 和渲染预览。
- 不改 README 正文、顺序和链接。嵌入 README 需要用户另行同意。
- 不提交、不推送、不开 PR，除非用户明确要求。
- 不虚构采用量、基准、兼容性、评价和功能。
- 目标、范围、输出格式、修改位置任一有歧义时，先提具体问题并给出默认假设，方便用户回答"按默认来"。需求明确时直接做。

## 步骤

### 1. 先问语言

开始设计前，问用户 header 文字用什么语言，是否双语。不要自行假定。

- SVG 文字不会自动换行，需要手动拆行。
- 中文、英文、衬线、无衬线的字宽不同，每次改文案后重新渲染，不要只数字符。
- 只用系统字体栈，不加载远程字体。中文可加入 PingFang SC 等系统字体。

### 2. 读仓库

读 README、目录结构、包元数据、logo、截图、真实输出和已有的设计色值。分清哪些说法有证据，哪些没有。没有证据的不写进图里。

### 3. 先写五件事，再画图

```
项目类别：
主要用户：
主要动作：
最佳证据：
原生视觉材料：
```

原生视觉材料指项目真正处理的东西，例如集群关系、张量、表格、代码、图层、时间线、地图、图标、终端输出、生成物。

### 4. 冻结美术规格

```
配色：底色 / 前景 / 弱色 / 一到两个强调色
字体：系统字体栈 / 字号层级 / 字重对比
形态：圆角 / 线宽 / 网格 / 间距
母题：一个来自项目的重复视觉线索
构图气质：安静 / 编辑感 / 技术感 / 活泼 / 电影感
```

颜色直接写十六进制，先定再画。母题取自项目本身：终端工具用提示符和光标，图标库用关键线和镂空，研究项目用坐标和证据标签。不要给每个仓库套同一个模板。

### 5. 选构图

标题可以包含五部分：类别或技术语境、仓库名、一句具体描述、真实项目素材、小号元数据。位置、大小可调，也可省略。

构图模式：

- 分栏：一侧标题，另一侧项目结构或产物。只有一个清晰证据时用。
- 融合：图形、代码、截图和标题共用一个网格。
- 产出墙：几个真实产物斜向排列，标题占一格或留白。
- 背景证据：放大一个真实产物衬在标题后面，要保证对比度。
- 纯标题：项目极简且没有可信的视觉证据时，只用字体和留白。

选择前问四个问题：

1. 缩到 GitHub 内容宽度后，证据还能看清吗？
2. 一个产物就能解释项目，还是需要对比几个？
3. 标题会不会经常改？经常改就把 SVG 标题和位图证据分开。
4. 合并后更清楚，还是只是省了纵向空间？

证据太密（多页截图、细节多）时，用 SVG 标题加紧随其后的证据墙。几个产物缩小后仍可辨认时，可以合成一张 PNG 或 WebP。

### 6. 画 SVG

- viewBox 宽 1200，高 300 到 420。关键内容离边缘 48 到 64。
- 文件骨架：`role="img"`、`aria-labelledby`，加上 `title` 和 `desc`。按角色给 `g` 命名，保证手改方便。
- 绘制顺序：背景和主要结构线，仓库名和描述，真实项目素材，类别和元数据，最后才加仍然需要的装饰。到第四步已经清楚就停。
- 图形只用 `rect`、`circle`、`path`、`g`、`clipPath`；文字用 `text`、`tspan`；无障碍信息用 `title`、`desc`。不用脚本、`foreignObject`、外部图片、远程字体、重滤镜。
- 阴影用偏移的低透明度矩形，不用滤镜。
- 图形用项目真实结构的简化版。不要随机网格、光点、电路纹样。
- 含多张截图、照片或生成图时，导出 PNG 或 WebP。SVG 内引用相对路径的位图在不同渲染器里不可靠。
- 命令、链接和说明放在 Markdown 里，不要只放在图里。
- 字号按 900 CSS 像素宽度预览：关键文字（仓库名、一句话描述）不小于 20 单位，辅助标签不小于 18 单位。更小的文字只用于非必要的元数据（如类别小字、导航），删掉也不影响理解。

### 7. 渲染并检查

- 用 rsvg-convert 渲染成 PNG。没有时，可用带 librsvg 的 ImageMagick（`magick hero.svg hero.png`），或用 pip 把 cairosvg 安装到临时目录再渲染。
- 渲染引擎的字体和 GitHub 不同，以 GitHub 上的实际显示为准。
- 检查：文字或路径被裁切；文字在 900 像素宽度下过小；亮色和暗色 GitHub 背景下的对比度；缺少 `title`、`desc`、`viewBox` 或 alt 文本；装饰抢了仓库名的位置。
- 遮掉仓库名后，如果这张图能放到一个无关项目上，重做。
- 视觉素材只是装饰、没有解释项目时，重做。
- 每次只改一处，再渲染。两个版本表达一样清楚时，留下更简单的。

### 8. 交付

- 给出 SVG 文件路径和渲染预览。
- 提供嵌入片段，alt 文本要有意义：

```
<p align="center">
  <img src="./assets/readme/hero.svg" width="100%" alt="仓库名和一句话描述">
</p>
```

- 说明哪些文件没有动。询问是否嵌入 README。

## 参考参数（实测起点）

| 项目 | 取值 |
|---|---|
| 画布 | 1200 × 320 到 390，圆角 26 到 32 |
| 边距 | 56 到 68 |
| 类别小字 | 等宽或粗体，13 到 17px，字距 2 到 3，全大写 |
| 标题 | 65 到 76px，字重 700 到 780，字距 -1.6 到 -3 |
| 描述 | 24px |
| 导航或元数据 | 12px 等宽，第一项亮色，其余弱色 |
| 阴影 | 偏移约 (8, 10) 的深色矩形，透明度 0.12 到 0.4 |
| 配色 | 底色、前景、弱色加一到两个强调色，整张图约五色以内 |
| 文件大小 | 约 2 到 6 KB，可手改 |
