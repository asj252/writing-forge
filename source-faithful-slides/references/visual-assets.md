# 已有素材与插画

用户给了、或要求配合使用现成的图形素材（SVG 插画、图标、照片等）时读取。目标有两个：素材真正进入逐页设计；内容与视觉分开验收。

## 先建素材映射

做逐页内容表时就盘点素材：逐个看懂画的是什么（人物、动作、场景、物件、概念），再和报告内容对应起来，建一张映射表，随逐页内容表交付：

`页 ID → 素材（路径）→ 图形角色 → 放置区域 → 理由`

图形角色按**每一幅图**分，逐页内容表的「图形角色与素材」一栏也用这几类：一页可以有几幅图，各记各的角色；一页一幅图都没有，才记「无图及理由」。

| 角色 | 承担什么 | 空间 |
|---|---|---|
| 必要解释图 | 正文的解释：流程、位置关系、坐标、数据图、源图的忠实重绘 | 可以占正文空间 |
| 情境插画 | 帮读者认出人物、动作、场景或概念，不承载证据 | 服从正文，补留白 |
| 纯装饰 | 只营造气氛或主题识别 | 最低优先，可以没有 |
| 无图及理由 | 本页一幅图都没有：写明为什么（没有贴题素材、没有留白、内容不需要……） | — |

- 已有图表的页，图表记为「必要解释图」；决定不再追加插画时，另写「不追加插画」及理由，不记成「无图」。
- 映射覆盖全部授权页，每页都有记录（可以是「无图及理由」）；不能只在前几页象征性地用几张。素材比页面多时不必用完；和本稿主题没有关系的素材，不因为文件已经存在就硬塞进来。
- 源报告或旧的逐页表写了「装饰图：无」时，先判断这是已经确认的限制，还是当时根本没有安排插画；用户另外给了相关素材时，不自动理解为禁止使用，拿不准就问。
- 配图在初始构图时就考虑：在 Mermaid 草图里给插画留出区域，写明素材与角色；不要正文排满之后再找空位，那样只剩角落小图标。草图里的这个区域只是布局注释，另在内容稿里按页附上素材本身（图像链接或预览），让制作者看得见图（见 [图示与导航](diagrams-navigation.md)）。
- 不用数量凑：每页同一个角落放一个小图标，数量增加了，构图没有变。

## 插画补留白，不挤正文

- 先确定完整正文、数据与限定所需的可读空间，再放情境插画与装饰。不得为了放插画缩窄正文栏、缩小字号、挤压行距、下推说明，或把已经确认的步骤压紧。没有合适的留白就可以不放。
- 必要解释图与插画分开对待：流程、位置关系、坐标与数据图可以占正文空间；只负责气氛或识别的插画服从正文，不能借「视觉增强」把装饰升级成新的主内容区。
- 页面已经有图表、流程图、热图、路线图承担视觉时，通常不再加情境装饰；图表本身就是这一页的视觉主体。
- 以文字叙述为主、确有留白的页，可以大胆一些：把贴题的插画放大、淡化，放在文字后方当背景（图层在正文之下，可以被前景局部遮住），正文对比度、品牌识别与信息层级优先。「不挤正文」不等于「只能放角落小图标」。封面适合用一幅放大、淡化的主题图作背景。
- 背景是否过量，同时看面积、位置、纹理密度、对比度，以及和正文重叠的范围；同样的透明度，多人场景比单个人物重。透明度、尺寸与位置按实际底色和预览调，某一稿用过的数值只记为那一稿的实现值，不当成通用阈值。

## 不改变证据

加图不得改变数字、证据强弱或论证关系，也不挤压统计图。不能为了气氛把「未检出」配成胜利，把「进入候选名单」配成已经上场或表现优秀。用人物或物件示意一个定义时（例如两个人示意一次配对比较），标明是示意，不是真实实例。

## 反馈与认可范围

- 用户说某页「too much」「太挤」：只调这一页图形的尺寸、位置与淡化程度。用户指出插图「抢空间」时，先把正文恢复原样（位置、字号、文本框尺寸、图层顺序），再在剩下的留白里调整图形。一页的否定不触发全稿重排。
- 用户说某页「可以」「ok」：记下这一页与具体认可的部位（例如「P12 右栏背景插画」），照 [锁定页](locked-pages.md) 的确认范围保存；它只约束这一页，不扩展成全稿统一的做法。
- 已确认页的文案、数据、布局与视觉层分别记录确认范围。用户后来要求视觉增强时，只按授权改视觉层并另存版本，不默默扩大到改写内容。

## 内容与视觉分开验收

内容忠实、结构清楚、技术检查通过，不等于视觉合格；视觉好看，也不能抵消内容问题。交付前分开看：

1. **内容**：照 `SKILL.md` 的交付前核对（数字与限定、去向、用语、首屏、同步）。
2. **视觉**：映射里的素材是否真的上了页；每幅新增的图说得出用途，不只是「填空位」；在实际投影尺寸下看得清；比较加图前后正文的可用宽度、高度、字号、位置与阅读顺序：因为加了情境插画或装饰而让正文变窄、变小、下移或打乱已确认的顺序，就是挤了正文；必要解释图占用正文空间、用户授权的布局调整不在此列。
3. **节奏**：看整稿或连续页的缩略图：是否长段只靠文字和表格、是否反复同一种构图、是否还有贴题的素材没考虑。连续多页没有情境插画是提醒，不是自动判错；密集的数据比较页可以合理地不加。

交付说明写实际改了哪些页、怎么验证的，不只报素材数量。素材覆盖了几页只是检查线索，不是配额。

## SVG 放进 PPT 的技术检查

- PowerPoint 对 SVG 的裁切不完全遵从根元素的 `viewBox`：只改 `viewBox`，源图里视框外的文字、页脚或其他数据图形仍可能显示出来，盖住正文。裁切后一定打开实际的 PPTX 看。
- 只用多面板图里的一个面板时，另存一份派生 SVG，在派生稿里删掉其他面板的元素，原图不改。以 Matplotlib 导出的 SVG 为例：每个坐标轴面板是一个独立的分组（如 `axes_1`、`axes_2`），删掉不用的面板分组；共享的 `defs`（点标记、裁切路径、字形）必须保留，否则留下的面板会丢掉标记等元素。这是针对这类 SVG 的做法，不是通用的裁切算法；其他来源的 SVG 先看结构再定。
- 出处、许可与必要的限定写在图外的正文区，不依赖图里的文字，也不压成贴着页脚的小字。
