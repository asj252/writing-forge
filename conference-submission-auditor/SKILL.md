# 顶会论文提交审计员（后三关：数值对账、符号退化与双盲合规）

本技能针对自然语言处理与机器学习顶会投稿（如 ACL Rolling Review、EMNLP、NeurIPS、ICLR、ICML），执行**后三关硬核交付与合规审计**。前三关（核心宣称映射与过度宣称拦截、混淆变量与替代解释猎杀、知识库竞品撞车审计）由姊妹技能 `arr-paper-reviewer` 负责，二者合用构成完整的六关投稿守门流水线。

## 核心铁律：独立批判者（Role `c`）绑定与脚本实证

1. **强制绑定执行载体（`codex` + `gpt-6.1-sol` + `high`）与防覆盖快照隔离**：
   - 本技能（后三关）强制使用 **Codex CLI（模型 `gpt-6.1-sol`，推理强度 `model_reasoning_effort=high`）** 作为独立批判者 `c` 执行。
   - 严禁用宿主内建通用子代理或起草作者同一会话上下文替代独立批判者 `c`。
   - 可直接调用本技能随附的 `scripts/run_codex_submission_audit.sh`：
     - 默认以 `codex exec -s read-only --ephemeral --skip-git-repo-check -m gpt-6.1-sol -c model_reasoning_effort="high"` 启动无状态只读独立审计（默认要求宿主机具备 `bwrap` 只读沙盒；缺失时默认以退出码 `3` 拒绝启动，仅在显式设置 `ALLOW_DEGRADED_NO_BWRAP=1` 时启用 `chmod -R a-w` 只读副本工作区与前后全量 SHA-256 快照比对降级模式）；
     - 强制要求输出报告路径为全新的不存在文件（拒绝覆盖任何工作区内外的既有文件），并在审计前后对工作目录及送审说明中引用的全部外部输入文件执行 SHA-256 快照比对；
     - 当 CLI 非零退出或报告校验失败时，显式捕获退出码并将诊断日志持久化保存至 `<输出报告路径>.diag.log`；
     - **退出码契约**：默认 `0` 表示报告生成且通过格式与完整性校验（若设置 `REQUIRE_NO_BLOCKERS=1` 或向 `submission_precheck.py` 传 `--require-pass`，则仅在 `**总体判定：无阻断**` 时返回 `0`，有效 `**总体判定：有阻断**` 报告落盘后返回 `1`）；`2` 表示参数/路径冲突或报告校验未通过；`3` 表示未找到可执行 CLI 或缺少 `bwrap` 只读沙盒（未显式授权降级）；`4` 表示 CLI 执行或鉴权失败；`5` 表示只读快照校验失败。
2. **禁止肉眼跳读数字，必须脚本对账**：
   - 执行第四关与第六关时，`c` 必须先运行 `scripts/submission_precheck.py` 扫描稿件，并针对稿件引用的实验汇总文件（如 `summary_*.json`、`.csv`）运行只读 Python 对账命令，逐格核算差值，不得仅凭静态阅读宣称“数字一致”。
3. **送审包纯净性**：
   - 送审包仅含待审论文稿件、图表源码、实验汇总数据原件及只读核对脚本路径，不传作者的内部推理与自评打分。

## 第四关：正文数字 ↔ 图表 ↔ 实验原件 三方脚本对账（Tri-Party Numerical Reconciliation）

对稿件（Markdown、LaTeX `.tex` 或 Typst `.typ`）中出现的全部实验数字执行「正文文字 ↔ 图表单元格 ↔ 原始 JSON/CSV 产物」三方闭环核对：

| 核对项 | 必查细节与阻断判准 |
|---|---|
| **点估计与舍入一致性** | 正文引用的数字、表格单元格与 JSON/CSV 原件在按稿件展示精度舍入后是否完全一致（保留 $k$ 位小数时末位舍入容差为 $\pm 0.5 \times 10^{-k}$；连续指标四舍五入展示为整数时容差为 $\pm 0.5$；整数计数如样本量 $n$ 则要求精确零误差）？是否存在手抄错位（如把模型 A 的 $H_2$ 抄到模型 B 的栏位）？任何超出容差的偏差均记为 `[Blocker]`。 |
| **正负号与文字方向** | 指标的正负号含义在文字叙述与表格中是否一致？例如 $\Delta < 0$ 代表敏感度下降或误差降低时，正文不得写反方向或漏写负号（`[Blocker]`）。 |
| **粗体/下划线最优标记** | 表格中标为粗体（最优）或下划线（次优）的单元格，是否确实是该列/该行的数学极值？若有并列极值是否按统一规则处理？ |
| **样本量 $n$ 与分母核对** | 表头、图注与正文中声明的计划单位数、有效单位数（如 `1400/1400`、`278/300`）及有效配对数 $n$（如 `n=120`、`n=98`）是否与原件完全吻合？ |
| **置信区间与多重比较** | 95% 置信区间 `[lower, upper]`、$p$ 值、Holm–Bonferroni 逐步校正阈值 $\alpha_{\text{Holm}}$ 以及假设检验是否被拒绝（`rejected: true/false`）的判定，是否与统计汇总原件逐项一致？ |

## 第五关：理论符号严谨性与读者认知流（Math Rigor & Reader Mental Model）

融合数学严谨性审查与皮亚杰（Piaget）读者认知模型审查，重点检查以下三类问题：

### 1. 符号定义闭环与跨节一致性
- 建立全文符号索引表（Symbol Index）：每个数学符号、上下标、集合与算子是否在首次出现时即给出明确定义与取值范围？
- **拦截同名异义与同义异名**：全文是否出现同一符号代表两个不同概念（例如在自然语言推理论文中，同时用 $H_2$ 表示“第二条预注册假设”和“二阶雷尼熵”，却未在符号或排版上加以区分），或同一指标在正文、表格与图注中使用了不同的缩写名称？

### 2. 退化与边界情形（Degenerate & Boundary Cases）
逐一核查文中定义的每个公式、指标或算法在极端输入下是否良定义（Well-Defined），且正文的数学定义与代码实现完全一致：
- **除零与权重退化**：当多候选口述权重总和 $\sum_{k=1}^K W_k = 0$、权重为负或偏离容差范围时，公式与代码是如何处理的（归一化、回退等权，还是记为解析缺失）？
- **零方差与常数输出**：当模型给出的所有候选估计完全相等（离散度 $\text{SD} = 0$）或所有样本预测值恒定不变时，比值指标（如相对变化百分比 $\Delta\text{SD}\%$）或相关系数是否有界？
- **平手情形（Ties）与端点堆积**：计算非参数排序指标（如 $\text{ROC-AUC} = \Pr(\Delta P_S > \Delta P_W) + \frac{1}{2}\Pr(\Delta P_S = \Delta P_W)$）时，平手项 $\frac{1}{2}$ 的处理是否写清并与代码一致？

### 3. 读者认知流与图表自明性（Reader Mental Model & Self-Contained Figures）
- **内部工作区代号外泄拦截**：默认审稿人完全不了解作者团队的内部工作流。严查正文中是否残留未向读者解释的内部工程简称、阶段编号、任务代号（如未定义先出现的 `Block-A`、内部配置键名、角色代号等）。
- **图表自明性（Self-Containment）**：审稿人往往先看图表再读正文。检查每张 Figure 与 Table：仅阅读标题、行列标签、图例与 Caption，能否在不翻找正文的情况下读懂（1）评测的数据拆分与样本数 $n$、（2）各缩写列的含义与单位、（3）数值越高越好还是越低越好（$\uparrow / \downarrow$）、（4）该图表的核心一句话结论？

## 第六关：双盲匿名与顶会提交合规清单（Double-Blind Anonymity & Submission Checklist）

运行 `scripts/submission_precheck.py` 并结合全文审查，逐项核验顶会提交红线：

1. **双盲匿名零泄漏（Double-Blind Anonymity，违反记为 `[Blocker]`）**：
   - 正文、脚注、附录、图表及附带脚本中不得出现本机或云端用户主目录绝对路径、本地文件协议链接、盘符路径、作者个人 GitHub 用户名、私有仓库名、未匿名化的在线文档链接或个人邮箱。
   - 检查自引语气：是否将作者既有工作以第三人称客观引用，而非暴露身份的 “In our previous work [X], we proposed...”？
   - 提交审核稿中是否误留了致谢（Acknowledgments）、基金编号或作者署名栏？
2. **顶会必交章节完备性**：
   - **Limitations（局限性独立小节）**：是否包含独立的 Limitations 节？内容是否诚实反映了实验的真实边界（如部分小模型在多估计格式下的解析截断率、固定采样温度的局限、特定语言或数据集范围），而非空洞套话？
   - **Ethical Considerations / Broader Impacts**：是否说明了数据集许可证、API 调用合规性与潜在伦理风险？
   - **Reproducibility Statement（可复现性要素）**：是否完整交代了提示词模板、采样参数（`temperature`, `top_p`, `max_tokens`, `seed`）、模型精确版本号（含日期后缀或快照名）及统计检验重跑方法？

## 报告输出规范

审计报告统一输出为结构化 Markdown，必须包含以下四个部分，并在全文最后一行给出可由程序严格解析的独立总体判定（校验器将同时扫描正文与代码围栏内部，严禁将 `MISMATCH` / `FAIL` 藏入代码块或以“静态阅读/后续补交”跳过脚本对账）：

1. **一、三方数值对账矩阵（Tri-Party Numerical Reconciliation Matrix）**
   - 必须包含实际已执行的对账脚本/命令（如 `python3 submission_precheck.py ...`），并输出包含具体数值与执行状态的逐格核对表：`位置（表/节） | 指标与模型 | 稿件数值 | 原始 JSON/CSV 数值 | 差值 | 状态（PASS / MISMATCH）`（其中 `差值` 统一定义为 `稿件数值 - 原始 JSON/CSV 数值`，或填写非负绝对差值 `|稿件数值 - 原件数值|`；若填写带正负号的差值则符号方向必须严格等于 `稿件数值 - 原件数值`）。
2. **二、数学符号、边界退化与认知流审计表（Math Rigor, Edge Cases & Cognitive Flow）**
   - 表格列出：`类别（符号冲突 / 边界退化 / 内部代号外泄 / 图表自明性） | 精确位置 | 问题描述与反例 | 最小修改建议`。
3. **三、双盲匿名与提交合规核对表（Anonymity & Compliance Checklist）**
   - 逐项列出 `scripts/submission_precheck.py` 与人工核查结果（`PASS / FAIL` 及行号）。
4. **四、分级修复清单（Prioritized Fix List）**
   - 按 **`[Blocker 阻断]`**（第四关数值 `MISMATCH`、正负号写反、公式与代码不符，以及第六关双盲泄漏或缺少必交合规小节导致的 `FAIL`——任何存在未豁免 `MISMATCH` 或 `FAIL` 的报告均必须判为 `**总体判定：有阻断**`）、**`[Major 重要]`**（符号未定义、退化情形未说明、图表自明性不足等不直接触发四/六关 `MISMATCH`/`FAIL` 的重要问题）、**`[Minor 建议]`**（图表 Caption 补充说明、排版微调）分类列出。

**末行独立判定铁律**：
报告全文的**最后一个非空行**必须严格为以下二选一（不加尾随标点或解释文字，供自动化流水线 fail-closed 解析）：
- `**总体判定：无阻断**`
- `**总体判定：有阻断**`
