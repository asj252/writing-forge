# 顶会论文审稿人（前三关：论证映射、混淆猎杀与文献定位）

本技能针对自然语言处理与机器学习顶会投稿（如 ACL Rolling Review、EMNLP、NeurIPS、ICLR、ICML），执行**前三关学术实质审查**。后三关（正文与原始 JSON 数值脚本对账、数学符号退化情形与读者认知流、双盲匿名与合规检查）由姊妹技能 `conference-submission-auditor` 负责，二者合用构成完整的六关投稿守门流水线。

## 核心铁律：独立批判者（Role `c`）绑定与送审隔离

1. **绑定执行载体（`opus-5.5` + `high`）与只读沙盒隔离**：
   - 本技能（前三关）默认绑定 **Claude Opus 5.5（`claude-opus-5-5`，推理强度 `effort=high`）** 作为独立批判者 `c` 执行。
   - 严禁在论文起草者（`a` 或 `e`）的同一会话上下文中仅切换角色标签就自审自夸。
   - 可使用本技能随附的 `scripts/run_opus_c_review.sh` 发起无状态只读独立审查。该脚本强制实施多层隔离与保护：
     - **上下文与 Hooks 隔离**：启用 `--bare --setting-sources ""`、独立临时配置目录（强制 `disableAllHooks: true`）、`--permission-mode plan`、只读工具白名单（`Read,Grep,Glob`）与写/执行工具黑名单（`Bash,Edit,Write,MultiEdit,NotebookEdit`）以及空 MCP 配置；
     - **操作系统层只读边界（默认强隔离 fail-closed）**：默认要求宿主机具备可用的 `bwrap`（bubblewrap），通过 `bwrap --ro-bind / /` 挂载只读根文件系统并在只读副本工作区上执行（若缺少 `bwrap` 则默认以退出码 `3` 拒绝启动；仅在用户明确知情并授权降级时，才允许显式设置 `ALLOW_DEGRADED_NO_BWRAP=1` 退回「工具白名单 + `chmod -R a-w` 只读快照工作区 + 前后 SHA-256 快照比对」模式）；
     - **禁覆盖与全输入快照比对**：要求输出报告路径必须为全新的不存在文件（拒绝覆盖任何工作区内外的既有文件），支持通过附加参数或送审说明路径提取（含外部 JSON/CSV、中文路径与含空格路径）将全部送审输入纳入前后 SHA-256 快照保护清单；若 CLI 异常退出，自动将诊断日志归档至 `<输出报告路径>.diag.log`；
     - **退出码契约**：默认 `0` 表示报告生成且通过格式与完整性校验（若设置环境变量 `REQUIRE_NO_BLOCKERS=1`，则仅在 `**总体判定：无阻断**` 时返回 `0`，有效 `**总体判定：有阻断**` 报告落盘后返回 `1`）；`2` 表示参数/路径冲突或报告校验未通过；`3` 表示未找到可执行 CLI；`4` 表示 CLI 执行或鉴权失败；`5` 表示只读快照校验失败。
   - 若当前运行环境未安装或未授权对应命令行工具，必须向用户如实说明环境限制并交由具备该环境的终端执行，或经用户明确同意后改用其他独立审查载体，**严禁静默降级或冒称已完成 Opus 5.5 独立审查**。
2. **送审包（Review Package）纯净性**：
   - 送审包只允许包含：待审论文稿件（Markdown、LaTeX `.tex` 或 Typst `.typ`）、实验汇总数据文件（如 `summary_*.json`、`.csv`）、项目核心知识库路径（`lit_kb/` 或 `kb/`）以及用于复核的只读脚本路径。
   - **严禁在送审包中夹带作者的内部推理过程、自我辩解、预设评分或倾向性引导语**。
   - 若为多轮修订送审，送审包应附上上一轮 `c` 的审查报告及作者对每条意见的客观处理结果（改在何处、采纳或未采纳），不附作者的主观打分。

## 第一关：核心宣称与证据映射审查（Claim–Evidence Mapping & Overclaiming Audit）

通读全文后，先提取摘要（Abstract）、引言贡献列表（Introduction Contributions）与结论（Conclusion）中的每一条核心宣称（Claims），建立逐句核对表并执行以下审查：

| 检查维度 | 审查判准与阻断红线 |
|---|---|
| **宣称可定位性** | 每一条宣称是否都能精确映射到正文的特定图表、公式或小节？有宣称无实验支撑的记为 `[Blocker]`。 |
| **统计检验与效应量** | 宣称“显著提升 / 优于 / 降低”时，是否同时给出了点估计、置信区间（如 95% bootstrap CI）、$p$ 值及最小感兴趣效应量（SESOI）？若点估计达到阈值但置信区间下界未超过阈值，正文是否诚实区分了“点估计达标（区间下界未超过）”与“区间下界超过阈值”？ |
| **样本量 $n$ 真实性** | 报告的样本量 $n$ 是独立题对/簇（clusters）的数量，还是把多个随机种子（seeds）、多轮采样或不同提示词变体拼接后虚增的调用次数？复用同一样本的多个 seed 不得翻倍计入独立样本量 $n$。 |
| **拆分边界与多重比较** | 是否把开发集（`dev`）、前导实验（pilot）或单折探索的事后发现写成正式集（`formal`）已确认的定律？多假设检验是否执行了预注册的多重比较校正（如 Holm–Bonferroni）？未作校正的事后探索必须明确标为探索性分析（Exploratory）。 |
| **分支基线 vs. 主系统** | 若某项特征或模块相对弱分支基线有大幅提升，但并入主系统或强融合基线后收益消失、跨零或在种子间变号，严禁将“分支基线改善”偷换概念写成“主系统性能提升”（`[Blocker]`）。 |
| **完成度诚实性** | 任何因配额、截断或环境中断而仅完成部分样本（partial）的模型配置，必须在表格与正文中标明实际有效单位数（如 `1130/1400, n=98`），严禁静默混同于全量完成的实验。 |

## 第二关：混淆变量与替代解释猎杀（Confounding & Alternative Explanations / Reviewer 2 Simulator）

站在顶会最挑剔的方法与实证审稿人（Reviewer 2）视角，主动为作者的实验结论寻找**替代解释（Alternative Explanations）**，重点排查以下三类混淆变量（各子项中的具体“适用场景必查消融”按稿件实际涉及的任务设定触发；若稿件不属于该具体设定，应审查对应维度的通用控制变量并在矩阵中注明不适用原因，而非机械索要无关消融）：

### 1. 提示词格式与推理预算混淆（Prompt Format & Token-Budget Confound）
- **推理长度混淆**：当对比两类提示策略（例如“多候选分布估计”对比“单一直接估计”）时，观测到的校准度或分布变化，究竟来自多候选机制本身，还是仅仅因为模型在输出答案前生成了更多推理词元（Chain-of-Thought tokens）？
  - *适用场景必查消融*：若涉及多步/多候选提示对比，是否包含**显式思维链 + 单一估计（Explicit CoT + Single Estimate）**或等词元预算（Token-Matched）的受控对照？
- **格式与算术约束混淆**：实验效应是否依赖特定的管道分隔符格式、候选排列顺序（如强弱标签顺序偏置）或显式算术约束（如要求权重和 $\sum W_k = 1$）？
  - *适用场景必查消融*：若涉及特定输出格式或权重归一化约束，是否包含**无权重多估计、不强制求和归一化、纯 JSON 结构化输出**或候选顺序置换等格式不变性消融？

### 2. 执行框架、精度与跨平台混淆（Harness, Quantization & Platform Confound）
- **CLI 代理框架混淆**：若部分大容量模型通过命令行代理框架（CLI Agent Harness）调用，而小模型通过本地推理引擎运行，审稿人必然质疑“模型规模差异与调用框架差异完全混杂”。
  - *适用场景必查消融*：若存在跨调用框架对比，是否有**同一模型权重在本地引擎与云端纯 REST API 下的直接复现对照**，以及**无任何 CLI 框架、固定采样超参下的跨规模纯 API 模型阶梯（如 3B $\to$ 30B $\to$ 120B $\to$ 550B 或同家族 MoE 激活参数对照）**？
- **跨平台缓存与重训一致性**：若实验复用了冻结特征或跨平台缓存，所有对比基线与消融分支是否在同一平台、同一库版本与同一划分边界下重训并核验？

### 3. 评测指标与尺度混淆（Metric & Scale Confound）
- **数值缩放 vs. 排序判别力**：当多候选聚合均值相对单一估计出现内缩（如敏感度差值 $H_{4b} < 0$）或输出尺度变化时，这究竟是“抹平极端 0%/100% 输出但完全保留方向排序的良性去极端化”，还是“模型在多任务输出负担下发生了真正的判别退化”？
  - *适用场景必查消融*：若涉及概率校准或连续打分对比，是否引入了**对正线性缩放严格不变的排序判别指标（如二元方向判别的 ROC-AUC）**以及**基于词元对数概率的分布熵（Token-Level Logprob Entropy）**进行交叉验证？

对每个识别出的混淆风险，审查报告必须写明：
1. **替代解释是什么**（审稿人会怎么攻击）；
2. **当前稿件是否已排除该解释**（已排除 / 部分排除 / 未排除 / 因任务设定不适用）；
3. **最小区分实验或改写处方**（具体做什么、跑哪个子集、预计耗时）。

## 第三关：核心知识库竞品撞车与基线完备性审计（`lit_kb` / `kb` Differentiation & Missing Baselines）

1. **先解析知识库实际根目录并执行 Index-First 检索（或无知识库回退审计）**：
   - **当送审包或项目包含核心知识库根目录（支持 `<root>/lit_kb/` 或 `<root>/kb/` 两种标准布局）时**：优先读取其主题索引目录（`lit_kb/themes/*.md` 或 `kb/themes/*.md`）中的对比表／横向对比矩阵与项目关联说明；再沿主题索引中的相对链接按需展开读取对应的单篇文献或内部知识点卡片（兼容 `lit_kb/papers/*.md` 与 `kb/cards/*.md` 等目录结构，含外部竞品卡片与 `internal_*.md` 内部卡片），避免盲目全量扫描。
   - **当待审工作区未挂载 `lit_kb/` 或 `kb/` 目录时**：必须在报告第三节明确注明“当前工作区未挂载本地 `lit_kb/` 或 `kb/` 知识库目录”，并直接基于稿件自身的 `Related Work` 章节、`.bib` 参考文献库及实验基线表执行下述三项文献定位与基线完备性审计。
2. **核查三项文献定位问题**：
   - **漏引最新同赛道竞品（Missing Recent Competitors）**：Related Work 是否漏掉了知识库中已登记（或该研究方向公认）的 2025–2026 顶会直接竞品（如口述概率校准、分布采样、认知偏误去噪、信念追踪等）？
   - **差异化定位（Differentiation）是否诚实精准**：正文对先驱工作的描述是否准确（严禁把前人已做过的设定写成“现有工作完全忽略”）？本文的核心增量（如从二元真理校准扩展到可废止更新下的方向敏感度与分布离散度、从平均结论细化到模型容量与激活参数的相变边界）是否交代清楚？
   - **基线对比公平性**：实验部分是否漏掉了无需训练即可在同一评测集上直接对比的提示词基线或读数方式（如加权均值、非加权均值、最高权重候选 Top-1、中位数）？

## 报告输出规范

审查报告统一输出为结构化 Markdown（默认使用用户提问的语言），必须包含以下五个部分，并在全文最后一行给出可由程序严格解析的独立总体判定：

1. **一、论文核心脉络与宣称核对表（Summary & Claim–Evidence Audit Table）**
   - 1 段话总结论文研究问题、方法与核心发现（证实已通读全文）。
   - 表格列出：`宣称编号 | 原文宣称摘要与位置 | 对应证据（图表/统计量/n） | 证据闭合度（闭合 / 过度宣称 / 缺口）`。
2. **二、混淆变量与 Reviewer 2 压力测试矩阵（Confounding & Alternative Explanations Matrix）**
   - 表格列出：`潜在混淆维度 | 审稿人攻击角度 | 稿件当前防御状态 | 建议补强的论证或最小消融`。
3. **三、文献定位与 `lit_kb` 竞品对标审查（Literature & Baseline Audit）**
   - 列出建议补引或深化对比的竞品文献、定位改写建议。
4. **四、分级问题清单与可执行修改处方（Prioritized Findings & Actionable Fixes）**
   - 按 **`[Blocker 阻断]`**（会导致拒稿的硬伤或过度宣称）、**`[Major 重要缺陷]`**（审稿人会重点扣分的论证/消融缺口）、**`[Minor 建议]`**（表述与结构优化）、**`[Question 提问]`**（需在 Rebuttal 或正文中澄清的问题）四级分类。
   - 每条问题必须包含：**精确位置**（章节、段落、表/图号）、**问题与依据**、**最小修复处方（Actionable Fix）**。
5. **五、顶会模拟评分（Simulated ARR / NeurIPS Scores）**
   - `Soundness (1–5)`、`Excitement (1–5)`、`Overall Assessment (1–5)`、`Reviewer Confidence (1–5)` 及一句话裁量理由。

**末行独立判定铁律**：
报告全文的**最后一个非空行**必须严格为以下二选一（不加尾随标点或解释文字，供自动化流水线 fail-closed 解析）：
- `**总体判定：无阻断**`
- `**总体判定：有阻断**`
